修改与依据：IK 采样出现逐字符哈希和范围比较；从原词典派生只读 BMP code/range 表，4 字节、非 canonical UTF-8 和分配失败均保留原路径。每个 DAT 范围增加 256 KiB，每个范围词典增加 128 KiB，生命周期跟随共享词典。原始词典和缓存格式不变。独占仲裁 map 去除 bucket 锁，TOKENIZE 空配置直接构造同样默认属性。查询采样出现逐条堆操作和字符集调度；对不需要评分的短自然语言并集直接归并 ID，同时推进重复 posting，输出前复制 ID，严格服从请求批量容量。评分、布尔和函数 lookup 保持原路径；binary ID 比较精确保留尾空格、NUL 和长度顺序。共享 `strcmpsp` 复用已经初始化的字符集 entry，冷初始化与非法参数仍按原逻辑处理。

## 瓶颈依据与修改

- IK 逐字符路径反复解码、分类，解析器重复建立只读字典 reader 和 cache pin。改为每字符解码一次，向各 processor 传递结果；字典 hub 懒初始化并复用只读 reader，保留冷启动锁、原子发布和正确关闭顺序。
- BENG 分词流水线存在临时对象和归一化后复制。改为内嵌组件并直接写入调用者 arena；合并等价的字符分类检查，限定可安全使用的 ASCII 长度快路径。
- 词频归并每词执行两次哈希定位和覆盖插入。改用已有 set_or_update，一次定位累加频次，并保留排序规则等价词的最后词形和首次词频约定。
- TOKENIZE 对已经验证的 JSON 配置重复序列化、反解析。直接生成相同的解析器属性，完整保留参数验证和错误行为。
- 每次评估独占的词频 map 仍有 bucket 锁。确认五处调用者的同步局部所有权后，统一使用现有无锁类型。停用词集合在启动前构建、停机后销毁，普通查找只读，也采用无锁容器；共享字典的初始化和发布同步保留。
- 自然语言 MATCH 仅作正数 WHERE 谓词时仍计算未使用的 BM25。对使用范围作保守判定，跳过评分专用列、统计和逐 posting 计分，以去重并集输出 ID。分数投影、排序、布尔模式、非零阈值、额外谓词、子查询和 LIMIT/OFFSET 继续走原评分路径。
- 构建采样中出现字符排序、比较和 sort 热点。UTF8 general_ci 完全相同字节直接返回相等；ASCII 解码使用快路径，保留 Unicode 权重、非法输入 fallback 与尾空格规则。

采样和 BENCHMARK 分词诊断只用于定位方向，不纳入计分。曾尝试 IK 同字符编码缓存，完整结果回归通过但没有稳定收益，已撤回，保留实验记录。

## 正确性

最终候选通过 408 组完整分词/词频/文档长度、144 组排名与分数、920 组谓词、144 组并发首次分词、768 组配置/错误码、280 组批次边界、1,440 组并发 ID/排名/分词、510 组独立推导的停用词并发检查、810 组 IK 交叠前缀完整输出，以及 27 类、52,963 行共享字符比较结果核对。排名分数容差为 1e-12。
正常开关库两次通过，并验证持久化全文索引。期望快照只在哈希已核验的未修改原版记录；候选不生成期望结果。

回归曾发现放开无分数 LIMIT/OFFSET 会在批次边界返回错误 ID，已限制该优化范围并补充计划断言。
所有基准查询命中数为 8001、11000、7332、20；这些数量只是辅助检查，完整结果回归另行执行。
