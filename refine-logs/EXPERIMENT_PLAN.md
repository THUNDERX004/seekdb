# MiniVectorDB 实验计划

日期：2026-11-09；官方加赛基线 a3dba559c1e7ebdc48bc990ffb1a4c75d1c1075c；本地优化对照 3659b39d6de0537fb81bd08a70b6f580c4e26f37。只在独立加赛工作树和 2026-competition-round2 分支工作。

## 主张与反证

| 主张 | 最少证据 | 不能据此声称 |
| --- | --- | --- |
| C1：在同一开发机和负载下减少执行耗时 | 同轮同种子、串行交替先后、三轮原始数据、两组查询全量校验、重启全内容校验 | 正式 E、物理磁盘 I/O、cgroup 内存或榜单名次 |
| C2：优化保留通用 SQL/事务/恢复及精确排序语义 | 官方公开断言、确定性反例、独立随机状态机、极端 float32 的整数真值、默认及强制标量构建 | 未公开隐藏 case 已全部通过、任意资源限额下均正确 |

反证目标：排除预存答案、只测公开样例、只校验抽样 Recall、漏掉列名/错误、跨轮挑最佳成绩、将参考执行器的浮点舍入误当数学并列。

## 五个实验块

1. 功能与合同（必须）：5 组32条官方 SQL；不改 mysqltest；额外检查真实列名、空断言成功状态和受影响行数。
2. 优化与诊断（必须）：CRC/序列化/输入解析、流同步、磁盘扫描流复用、候选索引和有界选择；保留各机制的历史三轮消融。旧 bench.py 混入 SQL 生成开销，仅作诊断；合并改动不能精确归因单个函数。
3. 同机主对照（必须）：10000行、128维、1000查询（各500条有/无过滤）、K10、每批100行提交；种子20261109/10/11；每条查询与独立真值比较，重启逐列核对全部10000行。最终源码改变后必须生成新的二进制指纹和报告，不覆盖历史测量。
4. 超缓存与隐藏边界（必须）：1MiB行缓存、3000行/40查询三轮；默认与 MVD_FORCE_SCALAR 编译构建完整回归；随机状态机加长；针对跨表txid、近距离、多排序键、alias、NULL、DDL和极大分页独立反例。近等距离增加Python整数真值，不削弱原断言。
5. 开源方法增量实验（必须）：只读查阅 Faiss v1.12.0 查询对象/批处理和 HNSWlib v0.8.0 CPU dispatch；不复制代码、不引入现成数据库或向量索引代执行。自研查询级探针预转换与内核选择，三轮比较是否保留。近似索引和额外全量向量副本为未实施方向，不宣称性能。

## 执行顺序与门槛

合同/基线 → 单机制测量 → 自研候选 → 独立边界/随机复核 → 默认及标量回归 → 最终三轮主/超缓存对照 → 文件指纹、diff、版本材料 → commit 后立即 push。

先正确性，后测量；不并行运行性能负载，不改变官方参数或存储持久化要求，不占用正式提测次数。性能波动保留每轮数据和范围，不只选最快一次。

## 环境和边界

Windows x64、CMake/Ninja、GNU 16.2；Docker daemon/可用WSL Linux缺失，未执行 Docker build、Linux评测或cgroup v2资源采集。峰值working set、commit charge和GetProcessIoCounters仅为诊断；管道I/O不能替代物理设备I/O，行缓存预算不是进程内存上限。

ARIS采用 experiment-plan、system-profile、analyze-results；正式 experiment-audit/result-to-claim 所需 reviewer MCP 后端不可用，状态 REVIEW_UNAVAILABLE。同模型子代理审查不冒充跨模型正式审计。
