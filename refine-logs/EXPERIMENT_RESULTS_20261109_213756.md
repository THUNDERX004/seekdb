## 反例 → 修复 → 复测

| 问题 | 旧版实际行为 | 修复 | 证据 |
| --- | --- | --- | --- |
| 以分号结束、stdin 仍打开 | BEGIN;、错误请求和相邻请求末条均等待后续字节，3 秒内无响应 | 删除无条件逐字节 peek，仅在识别注释/引号时按需前看，分号立即执行和 flush | round4-stdio-before.txt、round4-stdio-after.txt；实际 Popen 管道，不补换行或 EOF |
| 纯注释、尾注释或注释加空分号 | 多输出 ERROR SQL_SYNTAX 及 marker，请求/响应数不一致 | 复用 Parser 已分析 token，无 SQL token 时返回 nullopt，不产生响应；未闭合注释仍报错 | 同上；9 项测试方法含多个子场景 |
| VARCHAR 接受裸标识符 | DELETE FROM t WHERE s=missing; 将 missing 当成文本，删除实际匹配行；INSERT、UPDATE 也会写入错误文本 | VARCHAR 分支不再接受 Identifier；失败发生在数据修改前；保留既有数字字面量处理，不猜改未冻结隐式转换 | round4-sql-before.txt（10 项中 4 失败）、round4-sql-after.txt（10 项全过） |

新增测试要求非空错误码与无副作用，不固定未冻结映射，也不把未知转义、函数同名列等当作正式 oracle。默认输出、header/marker 开关、CLI 均不变；没有改成 JSON 协议，没有减少 fsync 或修改事务发布/恢复机制。

### 分析与取舍

1. 主写入三轮均更快，符合删除无条件 peek 减少输入开销的机制解释，但不是独立消融证明。主查询变化约 1%，且一轮更慢，不宣称稳定查询优化。
2. 超缓存初测 +2.61%，补测七轮 +0.25%，全部十轮仍 +1.01%；不能用补测掩盖负项或证明没有代价。保留小而必要的正确性修复，不为小幅差异引入未经验证的新扫描机制；后续需 Linux 合同下复核。
3. 主候选 Windows PeakWorkingSetSize 中位数 15745024 B，对照 15433728 B，增加 304 KiB；超缓存两组候选略低。PeakPagefileUsage 是提交内存，不是磁盘页文件 I/O。完整指标在原始 JSON。
4. 这是 Windows 开发数据，不是正式 cgroup 内存、物理磁盘 I/O、官方 E 或排名，不计算/承诺赛事分数。
